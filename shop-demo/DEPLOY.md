# วิธีเอาเดโมศิลาดลขึ้นเน็ต (อ่านก่อนกด deploy)

## 🔴 อย่าเอาขึ้น Vercel ทั้งอย่างนี้ — เดโมจะพังกลางทาง

`src/lib/store.ts` เก็บออเดอร์ไว้ใน **หน่วยความจำของโปรเซส** (`globalThis`)

Vercel รันแบบ serverless = แต่ละ request อาจตกไปคนละ instance
ลูกค้ากดชำระเงินที่ instance A แล้วหน้าจอ poll `/api/order/[id]` ไปโดน instance B
→ **"ไม่พบคำสั่งซื้อ" ทั้งที่เพิ่งกดจ่ายไป** เดโมพังต่อหน้าลูกค้าพอดี
(README ต้นทางเขียนเตือนไว้เองในหัวข้อ Deploy แต่ยังแนะนำ Vercel ไว้ด้านบน — ยึดตามคำเตือน)

**เอาขึ้น Vercel ได้เมื่อเปลี่ยน store เป็น Postgres แล้วเท่านั้น** (ดูข้อ "ก่อนขึ้นโปรดักชัน" ใน README)

## ✅ ทางที่ถูกสำหรับเดโม: Render Web Service (Node)

Render รันเป็นโปรเซสเดียวยาวๆ = ออเดอร์ที่อยู่ในหน่วยความจำยังอยู่ครบทั้งรอบที่ลูกค้าลองเล่น

สร้าง service ใหม่บน dashboard (repo เดิม ไม่ต้องแยก repo):

| ช่อง | ค่าที่ต้องกรอก |
|---|---|
| Repository | `jarkkitni/forex-ai-demo` (ตัวเดียวกับเซิร์ฟเวอร์ Flask เดิม) |
| Name | `siladon-shop-demo` |
| Language / Runtime | **Node** |
| **Root Directory** | `shop-demo` ← สำคัญที่สุด ลืมข้อนี้ Render จะไปสร้าง Flask แทน |
| Build Command | `npm ci && npm run build` |
| Start Command | `npm start` |
| Instance Type | Free ก็พอ |

Environment variables:

```
PAYMENT_DRIVER=mock
CRON_SECRET=<สุ่มมาสักชุด ห้ามใช้ change-me>
NEXT_PUBLIC_SITE_URL=https://siladon-shop-demo.onrender.com
```

> `next start` อ่าน `PORT` ที่ Render ตั้งให้เองอยู่แล้ว ไม่ต้องใส่เพิ่ม

⚠️ **Free instance หลับหลังไม่มีคนเข้า 15 นาที** ครั้งแรกที่ลูกค้ากดลิงก์จะรอ ~30-60 วิ
ถ้าจะส่งลิงก์นี้ให้ลูกค้าดูสดๆ ให้เปิดหน้าเว็บอุ่นเครื่องไว้ก่อนนัดสัก 1 นาที

## หลัง deploy เสร็จ ต้องทำต่อ

1. เปิด `https://<โดเมนที่ได้>/` แล้วลองซื้อจริงให้ครบลูป: เลือกสินค้า → ตะกร้า → ชำระเงิน → กด "จำลองจ่ายสำเร็จ" → ต้องขึ้น "ได้รับเงินแล้ว"
2. เอา URL ที่ได้ไปใส่การ์ดในหน้าแรก (`botkit.html` ส่วน `id="tools"`) ให้คนแวะเว็บกดลองได้
3. ถ้าจะเปิด cron reconcile: ตั้ง cron-job.org ยิง `GET /api/cron/reconcile`
   พร้อมเฮดเดอร์ `Authorization: Bearer <CRON_SECRET>` (ตอนนี้ยิงเปล่าๆ จะได้ 401 ถูกแล้ว)

## บันทึกการแก้ที่ทำไปแล้ว (13 ส.ค. 2026)

- **อัป `next` 15.1.0 → 16.3.0 + react 19.2.x** เพราะ 15.1.0 มีช่องโหว่ระดับ critical
  (`npm audit` เดิมขึ้นยาวเป็นหน้า รวม CVE-2025-66478) หลังอัปเหลือ **0 vulnerabilities**
  โค้ดไม่ต้องแก้เลยสักบรรทัด — `params` เป็น Promise อยู่แล้วซึ่งตรงกับ Next 16
- ลบ `tsconfig.tsbuildinfo` (ไฟล์ build ที่ติดมาใน zip) และโฟลเดอร์เปล่า `src/{app,lib,components}/`
  ที่เกิดจาก brace expansion ไม่ทำงานตอนแพ็ก zip

## ทดสอบแล้วผ่านทั้งหมด (บนเครื่อง)

`npx tsc --noEmit` ผ่าน · `npm run build` ผ่าน (15 หน้า) · `npm audit` = 0

| ทดสอบ | ผล |
|---|---|
| ซื้อครบลูปผ่านหน้าเว็บจริง | ตะกร้า → ชำระ → QR → จำลองจ่าย → **"ได้รับเงินแล้ว"** หน้าเปลี่ยนเองไม่ต้องรีเฟรช |
| แก้ราคาผ่าน API (ส่ง `price:1` มาด้วย) | เซิร์ฟเวอร์ไม่สนใจ คิดราคาจาก catalog เอง ฿890×2 = ฿1,780 |
| ยิง `/api/mock/pay` ซ้ำ | สถานะยัง `paid` เท่าเดิม ไม่นับซ้ำ |
| ข้อมูลที่ส่งออก client | ไม่มี `paymentRef` หลุด · QR หายทันทีที่จ่ายแล้ว |
| สั่งเกินสต็อก (แจกันร้าวเหลือ 3 สั่ง 5) | 409 พร้อมข้อความบอกจำนวนที่เหลือ |
| qty 0 / ติดลบ / ข้อมูลไม่ใช่ JSON / ไม่มีสินค้านั้น | 400 / 400 / 400 / 404 |
| `/api/cron/reconcile` ไม่มีกุญแจ | 401 |
