ร้านที่รับโอนผ่านพร้อมเพย์เจอปัญหาเดียวกันหมด คือสลิปปลอมและสลิปเก่าที่ส่งซ้ำ ดูด้วยตาแทบแยกไม่ออก เพราะแอปแต่งสลิปทำออกมาเหมือนจริงมาก บทความนี้อธิบายว่าระบบตรวจสลิปอัตโนมัติทำงานยังไง ต้องเช็คอะไรบ้างถึงจะกันโกงได้จริง และจุดไหนที่ระบบส่วนใหญ่ลืมเช็ค

ทำไมดูสลิปด้วยตาไม่พอ

  • ตัวเลข ชื่อ เวลา บนรูปสลิปแก้ได้ทั้งหมด รูปไม่ใช่หลักฐานว่าเงินเข้า
  • สลิปจริงที่เคยใช้แล้ว ส่งซ้ำมาอีกรอบก็ดูถูกต้องทุกอย่าง
  • สลิปจริงแต่โอนเข้าบัญชีคนอื่น (เช่น ร้านอื่นที่ชื่อคล้ายกัน) แอดมินที่รีบๆ มักไม่ได้อ่านเลขบัญชีปลายทาง

วิธีที่ชัวร์ที่สุดคือดูยอดเข้าในแอปธนาคารของร้านเอง แต่ถ้าวันละหลายสิบรายการ คนทำไม่ไหว จึงต้องใช้ระบบตรวจสลิป

ระบบตรวจสลิปทำงานยังไง

สลิปโอนเงินของธนาคารไทยเกือบทุกเจ้ามี QR เล็กๆ ที่มุมสลิป ข้างในเป็นรหัสอ้างอิงของรายการโอนนั้น ระบบตรวจสลิปจะอ่าน QR นี้ แล้วส่งรหัสไปถามข้อมูลจริงจากฝั่งธนาคาร ได้กลับมาเป็นข้อมูลรายการจริง เช่น ยอดเงิน เวลา บัญชีผู้โอน บัญชีผู้รับ

รูปสลิป → อ่าน QR มุมสลิป → ส่งไปผู้ให้บริการตรวจสลิป → ได้ข้อมูลรายการจริงจากธนาคาร → เทียบกับคำสั่งซื้อ

ข้อสำคัญ: ตัวเลขที่ใช้ตัดสินต้องมาจากผลที่ API ตอบกลับ ไม่ใช่จากตัวหนังสือบนรูป เพราะรูปแก้ได้ แต่ข้อมูลจากธนาคารแก้ไม่ได้

ผู้ให้บริการที่คนไทยใช้กันมีหลายเจ้า เช่น EasySlip, SlipOK, RDCW Slip Verify ส่วนใหญ่คิดค่าบริการเป็นแพ็กเกจรายเดือนตามจำนวนสลิป และมี API ให้นักพัฒนาเรียกใช้ได้ทั้งแบบส่งรูปและแบบส่งข้อความที่อ่านได้จาก QR

5 อย่างที่ต้องเช็คทุกครั้ง

  1. สลิปมีอยู่จริง — API ตอบกลับว่าพบรายการ ถ้าไม่พบ = ปฏิเสธทันที
  2. บัญชีผู้รับเป็นของร้าน — เทียบเลขบัญชีหรือเบอร์พร้อมเพย์ปลายทางกับบัญชีของร้าน (บางธนาคารแสดงเลขบัญชีแบบปิดบางหลัก ให้เทียบหลักที่เห็น พร้อมชื่อบัญชี)
  3. ยอดตรงหรือมากกว่ายอดที่ต้องจ่าย — โอนขาดแม้บาทเดียวก็ไม่ควรยืนยันอัตโนมัติ ส่งให้แอดมินดูแทน
  4. เวลาโอนอยู่หลังเวลาสร้างคำสั่งซื้อ — สลิปที่โอนก่อนลูกค้าจะกดสั่งซื้อ ย่อมไม่ใช่การจ่ายของออเดอร์นี้
  5. ไม่เคยถูกใช้มาก่อน — เก็บรหัสอ้างอิงของสลิปทุกใบที่ผ่านแล้ว และห้ามใช้ซ้ำ

จุดที่ระบบส่วนใหญ่ลืม: กันสลิปซ้ำให้ฐานข้อมูลเป็นคนกัน

บางผู้ให้บริการมีตัวเลือกเช็คสลิปซ้ำให้ แต่ร้านควรกันเองด้วย เพราะถ้าวันหลังเปลี่ยนผู้ให้บริการ ประวัติสลิปเก่าจะไม่ตามมา วิธีง่ายและปลอดภัยคือให้รหัสอ้างอิงสลิปเป็นค่าที่ซ้ำไม่ได้ในตาราง

create table payments (
  id            bigserial primary key,
  order_id      text not null,
  slip_ref      text not null unique,   -- รหัสอ้างอิงจากธนาคาร ห้ามซ้ำ
  amount        numeric(12,2) not null,
  paid_at       timestamptz not null,
  verified_at   timestamptz default now()
);

ถ้ามีลูกค้าสองคนส่งสลิปใบเดียวกันมาพร้อมกัน การเช็คในโค้ดก่อนบันทึกจะผ่านทั้งคู่ แต่ unique ในฐานข้อมูลจะยอมให้บันทึกได้แค่ครั้งเดียว อีกคนจะได้ error ซึ่งเราแปลงเป็นข้อความว่า "สลิปนี้ถูกใช้แล้ว"

เมื่อไหร่ควรส่งให้คนตรวจแทน

ระบบอัตโนมัติไม่จำเป็นต้องตัดสินทุกเคส ให้ยืนยันเองเฉพาะเคสที่ผ่านครบ 5 ข้อ ที่เหลือส่งเข้าคิวให้แอดมิน เช่น

  • ยอดโอนไม่ตรง (ขาดหรือเกิน)
  • อ่าน QR ไม่ได้ เพราะรูปถูกครอปหรือเบลอ — ขอให้ลูกค้าส่งรูปเต็มใหม่
  • API ของผู้ให้บริการล่มชั่วคราว — อย่าปฏิเสธลูกค้า ให้รอตรวจซ้ำหรือส่งให้คนดู

เรื่องความเป็นส่วนตัว

สลิปมีชื่อและเลขบัญชีบางส่วนของลูกค้า เก็บเท่าที่จำเป็น ไม่ต้องเก็บรูปสลิปไว้ตลอดไป เก็บแค่รหัสอ้างอิง ยอด เวลา ก็พอสำหรับกันสลิปซ้ำและตรวจย้อนหลัง

ดูตัวอย่างหน้าจ่ายเงินที่มีทั้ง QR และแนบสลิปได้ในเดโม เว็บรถเช่า และอ่านเทียบวิธีรับเงินแบบอื่นใน QR ตรวจสลิป vs Payment Gateway
