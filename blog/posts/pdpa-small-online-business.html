ร้านเล็กที่เริ่มมีเว็บจองคิว ระบบสมาชิก หรือแชทบอทเก็บเบอร์โทรลูกค้า มักถามว่า PDPA เกี่ยวกับเราด้วยไหม คำตอบสั้นๆ คือเกี่ยวทันทีที่เก็บข้อมูลที่ระบุตัวลูกค้าได้ ไม่ว่าร้านจะเล็กแค่ไหน บทความนี้สรุปเรื่องที่ร้านออนไลน์และคนทำระบบควรทำ ในมุมปฏิบัติ ไม่ใช่มุมกฎหมาย (ถ้าธุรกิจเก็บข้อมูลอ่อนไหวหรือข้อมูลจำนวนมาก ควรปรึกษานักกฎหมายเพิ่ม)

PDPA คืออะไร แบบย่อ

พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 บังคับใช้เต็มรูปแบบตั้งแต่ 1 มิถุนายน 2565 ใจความคือ ถ้าเก็บข้อมูลส่วนบุคคลของใคร ต้องบอกเขาว่าเก็บอะไร เอาไปทำอะไร เก็บนานแค่ไหน เก็บเท่าที่จำเป็น ดูแลไม่ให้รั่ว และให้เจ้าของข้อมูลขอดูหรือขอลบได้

ข้อมูลแบบไหนนับเป็นข้อมูลส่วนบุคคล

  • ชื่อ เบอร์โทร อีเมล ที่อยู่จัดส่ง
  • LINE User ID, Facebook PSID ที่ระบบแชทบอทเก็บไว้
  • รูปบัตรประชาชน ใบขับขี่ (ร้านรถเช่า ร้านเช่าชุด เก็บบ่อย)
  • สลิปโอนเงิน ซึ่งมีชื่อและเลขบัญชีบางส่วน

ข้อมูลสุขภาพ (เช่น ประวัติการรักษาของคลินิก) เป็นข้อมูลอ่อนไหว มีเงื่อนไขเข้มกว่า ต้องได้ความยินยอมแบบชัดแจ้ง

สิ่งที่ร้านควรทำ 6 ข้อ

  1. มีหน้านโยบายความเป็นส่วนตัว บอกว่าเก็บอะไร ใช้ทำอะไร เก็บนานเท่าไหร่ ส่งต่อให้ใครบ้าง (เช่น ผู้ให้บริการตรวจสลิป บริษัทขนส่ง) และติดต่อร้านช่องทางไหนเพื่อขอลบข้อมูล
  2. แจ้งตอนเก็บ ฟอร์มจองหรือหน้าสมัครสมาชิก ใส่ข้อความสั้นๆ พร้อมลิงก์ไปหน้านโยบาย
  3. เก็บเท่าที่ใช้จริง ระบบคิวไม่ต้องรู้วันเกิด ร้านขายของออนไลน์ไม่ต้องเก็บรูปบัตรประชาชน
  4. ขอความยินยอมแยกสำหรับการตลาด การส่งโปรโมชั่นเป็นคนละเรื่องกับการส่งของ ใช้ช่องติ๊กที่ไม่ติ๊กไว้ให้ก่อน
  5. กำหนดเวลาลบ เช่น ลบรูปบัตรประชาชนหลังคืนรถเรียบร้อย 30 วัน ลบรูปสลิปหลังตรวจผ่าน เก็บแค่เลขอ้างอิง
  6. มีช่องทางให้ขอลบ/ขอดูข้อมูล และตอบภายในเวลาที่เหมาะสม

ฝั่งคนทำระบบ: ตั้งค่าให้ถูกตั้งแต่แรก

  • ปิดสิทธิ์ฐานข้อมูลให้ถูก ถ้าใช้ Supabase ต้องเปิด Row Level Security ไม่งั้นใครถือ anon key ก็อ่านข้อมูลลูกค้าได้ทั้งตาราง (ดู Supabase RLS เบื้องต้น)
  • ไฟล์อัปโหลดอย่าเป็นลิงก์สาธารณะ รูปบัตรหรือสลิปควรอยู่ใน storage แบบ private และเปิดดูผ่านลิงก์ที่หมดอายุ
  • อย่าใส่ข้อมูลส่วนบุคคลใน URL เช่น ?phone=0812345678 เพราะไปค้างอยู่ใน log และประวัติเบราว์เซอร์
  • log อย่าเก็บข้อมูลเต็ม ปิดบางส่วนก่อนเขียน log เช่น 081-xxx-5678
  • key และรหัสผ่านอยู่นอกโค้ด (ดู กัน API key หลุด)
  • ทำปุ่มลบข้อมูลลูกค้าในหลังบ้าน ให้ร้านทำเองได้ ไม่ต้องรอโปรแกรมเมอร์

ถ้าข้อมูลรั่วต้องทำอะไร

กฎหมายกำหนดให้ผู้ควบคุมข้อมูลแจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส.) ภายใน 72 ชั่วโมงนับจากรู้เหตุ เว้นแต่การรั่วนั้นไม่น่าจะกระทบสิทธิของเจ้าของข้อมูล และถ้ากระทบสูงต้องแจ้งเจ้าของข้อมูลด้วย สิ่งที่ควรทำทันทีคือปิดช่องที่รั่ว เปลี่ยน key ที่เกี่ยวข้อง และจดบันทึกว่าเกิดอะไร เมื่อไหร่ ข้อมูลอะไรหลุด
