# ตั้งค่าระบบรับเงิน PromptPay (BotKit)

> ทำครั้งเดียวจบ ~5 นาที · ไม่ต้องสมัคร payment gateway ไม่มีค่าธรรมเนียม

---

## 1. เพิ่มคอลัมน์ใน Supabase (ทำก่อนอย่างอื่น)

เปิด Supabase → SQL Editor → รันทั้งก้อนนี้:

```sql
alter table botkit_orders
  add column if not exists pay_amount numeric(10,2),
  add column if not exists pay_status text,
  add column if not exists pay_note   text;

-- ใช้ค้นออเดอร์จากยอดเงินตอนกดยืนยัน (ยอด+เศษสตางค์ = ตัวระบุออเดอร์)
create index if not exists botkit_orders_pay_amount_idx on botkit_orders (pay_amount);
```

⚠️ **ไม่รัน SQL นี้จะเกิดอะไร:** PostgREST ปฏิเสธ **ทั้งแถว** เมื่อเจอคอลัมน์ที่ไม่รู้จัก
โค้ดจึงถอยไปบันทึกเฉพาะฟิลด์เดิมให้อัตโนมัติ (order ไม่หาย) แต่ **ยอดที่ต้องเก็บเงินจะไม่ถูกบันทึก**
และจะเห็นข้อความเตือนใน Render log ทุกครั้ง

`pay_status` มี 3 ค่า: `awaiting` (สร้าง QR แล้วรอโอน) → `slip_sent` (ลูกค้ากดแจ้งโอน) → `paid` (เรายืนยันแล้ว)

---

## 2. ตั้ง env บน Render

| ตัวแปร | ค่า | ไม่ตั้งแล้วเป็นยังไง |
|---|---|---|
| `PROMPTPAY_ID` | เบอร์ที่ผูกพร้อมเพย์ เช่น `0991350606` (หรือเลขบัตรประชาชน 13 หลัก) | ระบบจ่ายเงินปิดเงียบ ๆ · ฟอร์มสั่งซื้อยังทำงานเหมือนเดิมทุกอย่าง |
| `META_VERIFY_TOKEN` | มีอยู่แล้ว (ใช้ร่วมกับ webhook Meta) | กดยืนยันรับเงินไม่ได้ |

ตั้งเสร็จ Render จะ redeploy เอง ~1 นาที

---

## 3. เช็คว่าใช้งานได้จริง

เปิดหน้าแรก → กรอกฟอร์มสั่งซื้อ → ต้องเห็น **QR + ยอดที่มีเศษสตางค์** ทันทีหลังกดส่ง
เช่น `฿1,290.04` — ถ้าเห็นแค่ข้อความ "เราจะทักกลับใน 24 ชม." แปลว่า `PROMPTPAY_ID` ยังไม่ถูกตั้ง

## วิธีใช้งานประจำวัน

### เมื่อมีลูกค้าสั่งซื้อ

1. ลูกค้ากรอกฟอร์ม → เห็น QR พร้อมยอด เช่น `1,290.04` → สแกนโอน
2. ลูกค้ากดปุ่ม **"โอนแล้ว — แจ้งให้ทราบ"** → **LINE เด้งหาเรา** พร้อมยอดที่ต้องไปหา
3. **เปิดแอปธนาคารเช็คว่ามีเงินเข้ายอดนั้นจริง** ← ขั้นนี้ห้ามข้าม
4. เจอแล้วกดยืนยัน:

```bash
curl -X POST https://forex-ai-demo.onrender.com/api/pay/confirm \
  -H "Content-Type: application/json" \
  -d '{"token":"<META_VERIFY_TOKEN>","amount":1290.04}'
```

จะได้ LINE ยืนยันกลับมาว่า `✅ ยืนยันรับเงินแล้ว` และสถานะออเดอร์เปลี่ยนเป็น `paid`

## ทำไมยอดถึงมีเศษสตางค์

PromptPay แบบผูกเบอร์/เลขบัตร **ไม่มีช่องใส่เลขอ้างอิงที่ธนาคารส่งกลับมาให้เรา**
(จะมีได้ต้องเป็น Bill Payment ซึ่งต้องขอ Biller ID จากธนาคารก่อน)

ระบบจึงสุ่มเศษสตางค์ที่ยังไม่ถูกใช้ให้แต่ละออเดอร์ → เห็นเงินเข้า `590.37` ในแอปธนาคาร
= รู้ทันทีว่าเป็นออเดอร์ไหน โดยไม่ต้องเดาหรือไล่ถามลูกค้า

**ข้อจำกัดที่ยอมรับ:** ชนกันได้ถ้ามีออเดอร์ค้างจ่ายเกิน 99 ใบ *ของแพ็กเกจเดียวกัน* พร้อมกัน
(สเกลนี้ยังไม่ถึง — และถ้าถึงจริงคือปัญหาที่น่ายินดี)

## 🔴 กฎเหล็ก: ห้ามเชื่อสลิป

ระบบ **ไม่รับไฟล์สลิปและไม่อ่านสลิปด้วย AI โดยตั้งใจ** — สลิปปลอมทำง่ายมาก
และ AI อ่านตัวเลขผิดได้ ปุ่ม "โอนแล้ว" ของลูกค้าเป็นแค่การ**สะกิดเตือน**ให้เราไปตรวจ
ไม่ใช่หลักฐานว่าเงินเข้า

**เงินเข้าจริงหรือไม่ ดูจากแอปธนาคารเท่านั้น** — ข้อความ LINE ที่เด้งมาจะเตือนเรื่องนี้ทุกครั้ง

## ถ้าโตขึ้นแล้วอยากให้ยืนยันอัตโนมัติ (เฟส 2)

ทำเมื่อมีลูกค้าจ่ายจริงสม่ำเสมอแล้วเท่านั้น — ต่อ **Payso หรือ Beam** (non-bank gateway
สมัครได้ในไม่กี่วัน ไม่ต้องจดบริษัท ไม่ต้องมีทุนจดทะเบียน แค่มีบัญชีธนาคาร + เพจร้าน ค่าธรรมเนียม ~3–4%)

state machine (`awaiting → slip_sent → paid`) และหน้า UI จากเฟส 1 ใช้ต่อได้ทั้งหมด
สิ่งที่เปลี่ยนคือมี webhook มายิง `/api/pay/confirm` แทนเรากดเอง

⚠️ ค่าธรรมเนียม 3.65% ของ Omise = เสีย ฿21.5 ทุกเดือนต่อลูกค้า Starter หนึ่งราย
คิดให้ดีก่อนว่าคุ้มกับความสะดวกไหมตอนที่ยังมีลูกค้าไม่กี่ราย
